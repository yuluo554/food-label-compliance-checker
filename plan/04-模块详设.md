## 1. 标签参数卡 LabelCard（统一中间表示）

```python
@dataclass
class Evidence:
    region: str      # 标签区域：名称栏/配料表/营养成分表/日期栏/声称文字/其他
    quote: str       # 原文逐字摘录（必须是输入的子串，防幻觉硬校验）
    span: tuple[int, int] | None   # (start, end) 字符偏移，可空

@dataclass
class LabelField:
    key: str         # 参数键，见 §1.1 参数表
    value: Any       # 结构化值（标量/列表/嵌套表）
    unit: str | None
    confidence: float          # 规则命中 1.0；模糊/LLM 兜底 < 1.0
    evidence: Evidence
    raw: str | None            # 原始行

@dataclass
class NutritionRow:            # 营养成分表一行
    name: str                  # 能量/蛋白质/脂肪/碳水化合物/钠/…
    amount: float; unit: str   # 每 100g(mL) 或每份含量
    nrv_percent: float | None  # NRV%，能量/核心素必有，其他可空
    per_serving: bool = False

@dataclass
class LabelCard:
    fields: dict[str, LabelField]
    nutrition_table: list[NutritionRow]
    ingredients: list[str]           # 配料按标示顺序
    claims: list[str]                # 营养/功能声称原文
    unresolved: list[str]            # 疑似有值但未解析的片段（喂给 LLM 兜底/报"待人工"）
```

### 1.1 参数卡字段表（M2 按此实现，允许实现期增补）

| key | 值类型 | 来源区域 | 强制标示 |
|---|---|---|---|
| food_name | str | 名称栏 | ✅ |
| ingredients | list[str] | 配料表 | ✅ |
| net_content | {amount, unit, spec} | 净含量行 | ✅ |

| producer_name / producer_address / producer_contact | str | 生产者栏 | ✅ |
| sc_license | str（SC+14位） | 许可证栏 | ✅ |
| product_standard | str | 标准代号栏 | 视情形 |
| quality_grade | str | 等级栏 | 视情形 |

| claims | list[str] | 声称文字 | — |

## 2. 规则集与规则 schema（versioned ruleset）

```json
{
  "ruleset_id": "gb7718-2025",
  "title": "GB 7718-2025 预包装食品标签通则",
  "effective": "2027-03-16",
  "source_files": ["data/knowledge/raw/gb7718-2025.<ext>"],
  "rules": [
    {
      "id": "MAND-NET-01",
      "name": "强制标示：净含量",
      "check_type": "mandatory_field",
      "param": "net_content",
      "severity": "不合规",
      "basis": {"standard": "GB 7718-2025", "clause": "4.1.5", "quote_ref": "blocks#…", "status": "已核对|待核对"},
      "advice": "…整改建议…",
      "only_if": null,
      "params": {}
    }
  ]
}
```

约束：

- `basis.status` 只有"已核对（挂原文出处）"的规则允许输出**确定语气**结论；"待核对"规则输出自动附加"依据待核对"标注（写入 Finding，报告与 Web 同步显示）。
- `check_type` 枚举：`mandatory_field` / `format` / `nrv_recalc` / `energy_consistency` / `ingredient_order` / `claim_threshold` / `claim_whitelist` / `date_logic` / `conditional`。引擎按 type 分派到确定性 handler，**不开放自由文本判定**。
- `only_if` 门控对**全部** check_type 生效（含 conditional），关键词与品类语料互斥（M3 定稿门控词表并回归）。
- 营养素参数表（NRV 基准值、能量系数）独立成 `nutrient_reference.json`（挂 GB 28050 条款出处），规则表引用不复制。

## 3. 数值复算引擎（numeric/，纯确定性）

| 校核 | 逻辑 | 输出 |
|---|---|---|
| NRV% 复算 | 对表中每行：`round(amount / NRV(name,unit) × 100, 0)` 与标示值比对，容差 ±1（NRV% 修约间隔 1 已核对：两版附录A；数值修约总则 GB/T 8170 条款仍待核对） | 行级 finding：行名+复算值+标示值+依据 |
| 能量折算一致性 | `E_calc = 17×蛋白 + 37×脂肪 + 17×碳水`（系数已核对：GB 28050-2025 §2.3 原文"蛋白质 17、脂肪 37、碳水化合物 17 kJ/g"；标示膳食纤维时以 8 kJ/g 计），与标示能量比对（容差按允许误差表2：能量"实际 ≤120% 标示值"，两版已核对） | finding 挂系数表出处 |
| 声称阈值 | 声称词→阈值表（如"无糖 ≤0.5g/100g(mL)"，入库挂出处），含量不达阈值即不合规；"零添加/不添加"按 2025 版新规限制；功能声称对白名单 | finding 挂阈值条款 |
| 日期逻辑 | 生产日期+保质期 → 预计到期日 vs 标示"保质期到期日"自洽；日期格式规范（2025 版标示方式） | finding |

数值合法性前置：成分含量超出物理合理范围（负数/异常巨值）先丢弃并记 `unresolved`，不进复算。

## 4. 双标尺引擎与对照输出

- 引擎入口：`run_rulesets(card, ruleset_ids=["gb7718-2011","gb7718-2025"])` → `{"gb7718-2011": RuleResult, "gb7718-2025": RuleResult}`。
- `RuleResult = {findings: [Finding], stats: {checked, pass, fail, manual}}`；
- `Finding = {rule_id, level(合规|不合规|待人工确认), message, basis, evidence, advice, ruleset_id, flagged_pending_basis}`。
- 对照输出 `dual_diff`：以 2011 结果为基线，标注 2025 版**新增**不合规项与**放宽/取消**项——直接服务换版期需求。

## 5. Pipeline 编排

节点：`load_input → parse(→card) → [run_ruleset(2011), run_ruleset(2025)] → merge+diff → emit{json|docx|web}`。
每个节点记录耗时与状态；解析置信度低或 `unresolved` 非空 → 若 LLM 可用走兜底（标注 LLM 参与），否则进"待人工确认"级。任一节点失败：输入类失败（缺文件/坏编码）明确报错退出；规则类失败降级为该 ruleset 结果缺失+警告，不吞异常。

## 6. 基准设计（M4，零 API 依赖）

| 基准 | 真值来源 | 指标 |
|---|---|---|
| bench parse | 生成器真值参数卡（字段级） | 字段级 P/R/F1（目标 F1≥0.95） |
| bench e2e | 生成器注入的已知违规清单（主期望+also_expect 语义，按"文档全部非 pass 集合"对账） | 检出率 / 误报率 / 判定准确率（误报目标 0） |

真值语义（一次定清，M1 写进生成器注释）：注入项记主期望；同一注入隐含的其余结论记 `also_expect`；评测对账"全部非 pass 集合"而非单点。

## 7. 交付形态

- **CLI**：`flcheck parse|check|gen|bench|web`；`check --ruleset both --format json|table --report out.docx`。
- **Web**：单文件内联 HTML（vanilla JS）+ FastAPI 静态挂载；路由：`GET /`（面板）、`POST /api/check`（multipart 上传文本→完整 JSON）、`GET /api/health`。0 外链，`docs_url=None, redoc_url=None`。
- **docx 报告**：结论摘要 → 问题清单（分级）→ 证据表 → 整改建议 → 审查员签署栏 → 免责声明；"待人工确认"独立成节。
